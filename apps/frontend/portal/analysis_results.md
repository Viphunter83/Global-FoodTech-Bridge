# Глобальный FoodTech Bridge: Результаты экспертного аудита

## Общее резюме проблемы
Платформа на данный момент представляет собой гибрид между реальным Production-кодом (связь с сервером IPFS/Blockchain через API) и «заглушками» для демо-презентаций. Из-за этого пользовательские пути (User Flows) прерываются, данные не синхронизируются, а часть функционала работает только визуально. 

---

## 1. Доступ в Админ-панель
**Проблема:** В интерфейсе нет кнопки переключения ролей или прямой регистрации в качестве администратора. При попытке войти через аккаунт Google, пользователь все равно не видит админские функции.
**Причина (Техническая):** В компоненте `AuthProvider.tsx` указано: *«Security: roles are ONLY assigned through Firestore documents»*. То есть система авторизации ожидает, что в базе данных (Firebase Firestore) в документе вашего пользователя (`users/{uid}`) будет явно указано `role: "ADMIN"`. Если профиля нет, пользователю присваивается роль `PENDING`.
**Решение:** 
- Для работы в качестве админа необходимо вручную изменить роль через базу данных (или мы можем создать временный скрипт/инструмент, который назначает вас администратором). 
- Необходимо добавить UX-уведомление для `PENDING` пользователей о том, что их аккаунт ожидает подтверждения, чтобы это не выглядело как системная ошибка.

## 2. Разрыв Demo-режима и UserFlow (от создания до QR)
**Проблема:** Изначальный путь «Создал партию -> Отследил -> Отсканировал» разрушен из-за конфликта двух подходов создания партий.
**Причина (Техническая):**
- На странице `batches/new/page.tsx` реализовано **реальное** создание паспорта с выгрузкой в IPFS и записью в БД (`/api/passport/batches`).
- Однако на самом **Дашборде** (`dashboard/page.tsx`), при нажатии кнопки «New», модальное окно создает партию *локально в браузере* без вызова API. 
- Это генерирует случайный локальный UUID. При попытке посмотреть страницу верификации такого фейкового UUID (`/verify/[id]`), система ожидаемо ломается.
**Решение:** Полностью удалить локальные стейт-мокапы из `dashboard/page.tsx` и завязать все создание партий исключительно через вызов API-эндпоинта, унифицировав логику с `batches/new`.

## 3. Отслеживание и функционал Дашборда
**Проблема:** Дашборд выглядит интерактивно, но не несет реальной полезной нагрузки. Карточки статусов, температура и данные захардкожены.
**Причина:** Использование `MOCK_BATCHES` в `dashboard/page.tsx`.
**Решение:** Подключить дашборд к реальному эндпоинту бэкенда для получения списка партий (fetch).

## 4. Карта как полезный инструмент
**Проблема:** Карта (`LiveMap` / `DashboardMap`) выглядит эффектно, но является просто статичной абстракцией с "точкой" на случайных, зачастую не связанных с партией, координатах (захардкожено в код Дубай `lat = 25.276987, lon = 55.296249`).
**Решение:**
- Использовать реальные GPS-координаты для текущего этапа (Фабрика -> Порт -> Ритейлер).
- Проложить линию маршрута между `origin_country` и `destination_country`.

## 5. Цифровой паспорт и передача товара
**Где это происходит:** Паспорт успешно формируется в `/api/passport/batches` (сохраняет IPFS хэш). 
**Передача товара:** Реализована в `BlockchainControls.tsx` (кнопки логиста, ритейлера и т.д.), которые вызывают `/api/blockchain`. Однако из-за проблемы путаницы с локальными/реальными ID партий, этот механизм трудно запустить с дашборда.

## 6. Неработающие кнопки
**Причины:**
- **View Digital Twin (В дашборде)**: Пытается интерполировать строку `/${t.raw('locale')}/verify/${selectedId}`. Использование `t.raw` для получения языка часто вызывает fatal error или возвращает `undefined`. Необходимо использовать стандартную маршрутизацию `useLocale()`.
- **Документация на главной**: Ссылка ведет на `https://docs.gftb.bridge`, который не зарегистрирован.
- **Report Issue (в VerifyClient)**: Просто вызывает системный `alert()`. 
**Решение:** Либо внедрить реальные формы, либо скрыть кнопки, чтобы не портить "Production Readiness" статус системы.

## 7. B2B в B2C (Воронки продаж)
**Проблема:** Вы обещаете бизнесам (B2B), что ваш сервис станет воронкой продаж. Однако конечный потребитель, сканирующий QR-код и попадающий в Цифровой двойник (`VerifyClient.tsx`), видит только технические данные (сертификаты Халяль, Транзиты). Там нет кнопки "Купить еще продукцию этого бренда" или "Перейти в магазин", хотя компонент `MerchantFunnelCTA` в коде существует!
**Решение:** Встроить компонент лояльности (`MerchantFunnelCTA` / `MerchantDetailsCard`) прямо в `VerifyClient.tsx`, чтобы потребитель мог перейти на сайт партнера, тем самым реализовав ваше бизнес-вэлью.
